## 2. Kernel filename pattern — `drivers/bluetooth/btbcm.c` (torvalds/linux @ master)

Fetched from `https://raw.githubusercontent.com/torvalds/linux/master/drivers/bluetooth/btbcm.c`.

Subversion → hardware-name table (verbatim):

```c
{ 0x220e, "BCM20702A1"  },	/* 001.002.014 */
{ 0x2118, "BCM20702A0"	},	/* 001.001.024 */
{ 0x410e, "BCM20702B0"	},	/* 002.001.014 */
```

Filename construction at probe time (verbatim):

```c
		vid = get_unaligned_le16(skb->data + 1);
		pid = get_unaligned_le16(skb->data + 3);
...
		snprintf(postfix, sizeof(postfix), "-%4.4x-%4.4x", vid, pid);
...
	if (hw_name) {
		if (board_name) {
			snprintf(fw_name[fw_name_count], BCM_FW_NAME_LEN,
				 "brcm/%s%s.%s.hcd", hw_name, postfix, board_name);
			fw_name_count++;
		}
		snprintf(fw_name[fw_name_count], BCM_FW_NAME_LEN,
			 "brcm/%s%s.hcd", hw_name, postfix);
		fw_name_count++;
	}

	if (board_name) {
		snprintf(fw_name[fw_name_count], BCM_FW_NAME_LEN,
			 "brcm/BCM%s.%s.hcd", postfix, board_name);
		fw_name_count++;
	}
	snprintf(fw_name[fw_name_count], BCM_FW_NAME_LEN,
		 "brcm/BCM%s.hcd", postfix);
```

**CONFIRMED pattern:** `brcm/BCM20702A1-<vid4>-<pid4>.hcd` (also A0/B0 variants), fallback `brcm/BCM-<vid4>-<pid4>.hcd`. Note: vid/pid here come from the controller's *USB Product Info* HCI read, which for these dongles equals the USB VID/PID.

## 3. Package ownership (VERIFIED NEGATIVE on modern releases)

- **Debian trixie `bluez-firmware`** filelist (`https://packages.debian.org/trixie/amd64/bluez-firmware/filelist`) ships only 4 brcm hcd files: `BCM43430A1.hcd`, `BCM43430B0.hcd`, `BCM4345C0.hcd`, `BCM4345C5.hcd`. **No BCM20702A1.**
- **Ubuntu noble `bluez-firmware`** filelist (`https://packages.ubuntu.com/noble/all/bluez-firmware/filelist`) ships only BCM43xx / SYN43xx files. **No BCM20702A1.**
- **Debian trixie Contents search** for `BCM20702A1-0a5c-21e8.hcd`: `"Sorry, your search gave no results"` → no trixie package ships it.
- **Ubuntu noble Contents-amd64.gz** (51.3 MB, fetched from archive.ubuntu.com): **0 matches for `BCM20702A1`** → no noble package ships it.
- **Upstream linux-firmware WHENCE** (kernel.org was bot-blocked; used Endlessm GitHub mirror, 364 KB, 3,964 `File:` entries, genuine WHENCE header): **0 hits for `BCM20702`/`20702`; only `brcm/BCM-0bb4-0306.hcd`.** → linux-firmware does not ship BCM20702A1 firmware either.

Conclusion: on Debian trixie and Ubuntu noble, **no package ships BCM20702A1 firmware**. UNKNOWN whether historical releases (e.g. Ubuntu trusty-era `bluez-firmware`) shipped it — not verified here.

## 4. USB IDs in btusb.c (local capture `/tmp/dynid/btusb.c`, 4,754 lines, torvalds master)

Upstream btusb.c does **not** enumerate individual BCM20702 dongles by VID:PID. It matches them with vendor-wide class rows + `BTUSB_BCM_PATCHRAM`. Representative verbatim rows:

```c
/* Broadcom BCM20702B0 (Dynex/Insignia) */
{ USB_DEVICE(0x19ff, 0x0239), .driver_info = BTUSB_BCM_PATCHRAM },

/* Foxconn - Hon Hai */
{ USB_VENDOR_AND_INTERFACE_INFO(0x0489, 0xff, 0x01, 0x01),
  .driver_info = BTUSB_BCM_PATCHRAM },

/* Broadcom devices with vendor specific id */
{ USB_VENDOR_AND_INTERFACE_INFO(0x0a5c, 0xff, 0x01, 0x01),
  .driver_info = BTUSB_BCM_PATCHRAM },

/* Lite-On Technology - Broadcom based */
{ USB_VENDOR_AND_INTERFACE_INFO(0x04ca, 0xff, 0x01, 0x01),
  .driver_info = BTUSB_BCM_PATCHRAM },

/* ASUSTek Computer - Broadcom based */
{ USB_VENDOR_AND_INTERFACE_INFO(0x0b05, 0xff, 0x01, 0x01),
  .driver_info = BTUSB_BCM_PATCHRAM },
```

Also present: `{ USB_VENDOR_AND_INTERFACE_INFO(0x13d3, ...) }` (IMC Networks), `0x0930` (Toshiba), `0x050d` (Belkin), `0x413c` (Dell), `0x105b` (Foxconn/Lenovo BCM43142), `0x0bb4` (HTC Vive BCM920703).

⚠️ **Correction:** `0x0489:0xe03c` is **NOT** BCM20702 in this tree — it is `{ USB_DEVICE(0x0489, 0xe03c), .driver_info = BTUSB_ATH3012 }` (Atheros AR3012). `0a5c:21e8` has no explicit row; it is covered by the `0a5c` vendor-class row above.
